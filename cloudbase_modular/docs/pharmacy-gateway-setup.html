MAP Pharmacy Gateway — Setup & Deployment

Complete guide to deploying the pharmacy assessment gateway, provisioning site keys, and connecting pharmacy locations to PI workspaces.

Platform: atlas.adherence.cc
File: pharmacy.html
Deploy target: Cloudflare Workers
Last revised: July 2026
How the Gateway Works

The pharmacy gateway is a 5-screen kiosk page. A pharmacist accesses it via a site-specific URL. On load, the page validates the site code against the ATLAS Lambda, signs in with a scoped Firebase custom token, then presents the setup form. The pharmacist configures the session and hands the tablet to the patient. When a high-risk result occurs, the pharmacist can push an alert directly to the linked prescriber workspace.

Prerequisites
  • Wrangler CLI installed and authenticated (npx wrangler whoami should return your account)
  • Firebase CLI installed and authenticated (firebase login, project set to adherence-project-2026)
  • AWS CLI configured with access to the ATLAS SSM parameter store (aws sts get-caller-identity should succeed)

Deployment Steps
1
Deploy pharmacy.html to Cloudflare
cloudbase_modular/ → atlas.adherence.cc

Run Wrangler from the cloudbase_modular directory. This deploys all static assets including pharmacy.html to the Cloudflare Workers site.

Terminal — from cloudbase_modular/
npx wrangler deploy --config wrangler.prod.toml

Wrangler will output the deployment URL. Verify at https://atlas.adherence.cc/pharmacy.html?demo=true — you should see the MAP Assessment loading spinner and then the setup screen.

⚠
Deploy only when ready. This command deploys the entire worker and all assets. If other changes in the working directory are not meant to go live, stash or commit them first.
2
Deploy Firebase Security Rules
firebase/ → adherence-project-2026 RTDB

The rules update restricts pharmacy_assessments writes to authenticated workspace tokens only (blocking anonymous writes), and adds the new prescriber_alerts node.

Terminal — from cloudbase_modular/firebase/
firebase deploy --only database

The Firebase console should show the rules version incrementing under Realtime Database → Rules. Confirm that pharmacy_assessments and prescriber_alerts are present in the deployed rules.

✓
Rules file used: firebase/database.rules.json (referenced by firebase/firebase.json). The file firebase-rules.json in the root is the working master copy and is kept in sync.
3
Provision a Pharmacy Key in AWS SSM
AWS SSM Parameter Store → /atlas/workspaces/PHRM-*

Each pharmacy location needs a PHRM- prefixed key stored in SSM. The key is the site code that appears in the pharmacy URL.

⚠
Do not include an email field in the JSON value. If an email is present, the Lambda triggers a magic link flow, which is incompatible with a shared kiosk URL. The "no email" path issues a direct Firebase token, which is what the pharmacy gateway requires.
AWS CLI — provision a pharmacy key
aws ssm put-parameter \
  --name  "/atlas/workspaces/PHRM-SITECODE" \
  --value '{"name":"Pharmacy Display Name","role":"pharmacy","country":"Country Name","country_iso2":"XX","city":"City Name","latitude":0.0000,"longitude":0.0000,"parent_pi":"RESKEY-001","parent_institution_name":"Linked Clinic Name"}' \
  --type  SecureString \
  --region us-east-1

If the key already exists and you are updating it, add --overwrite to the command.

SSM JSON field reference:

Field Required Description
name required Pharmacy name. Pre-fills the "Pharmacy Name" field on the setup screen so the pharmacist does not need to type it each time.
role required Must be "pharmacy". Used by Firebase rules (role !== 'observer' check) and may be used for role-based UI logic in future versions.
parent_pi optional Links to a PI workspace. Set to the workspace key (e.g. "RESKEY-001") of the prescriber or research PI associated with this pharmacy. When present, the "Push to Workspace" button appears on the alert screen and alerts are written to prescriber_alerts/{parent_pi}/ in Firebase. Omit if the pharmacy is standalone.
parent_institution_name optional Human-readable label for the linked workspace — shown in the green "Connected to Workspace" badge on the setup screen and in the push button label. Falls back to parent_pi if omitted.
institution optional Pharmacy institution name. Used as the organisation header in the downloaded adherence report. Falls back to name if omitted.
country optional Country name (full). Stored on every assessment record. Used in reporting and data filters. Example: "United Arab Emirates", "Germany", "Philippines".
country_iso2 optional ISO 3166-1 alpha-2 country code. Example: "AE", "DE", "PH". Used for map filters and analytics grouping.
city optional City name. Stored on every assessment record for location-level reporting.
latitude optional Required for MAP globe plotting. Decimal latitude of the pharmacy location. Example: 24.4539 (Abu Dhabi). Without this field the assessment saves but does not appear as a dot on the ATLAS Mapbox global map.
longitude optional Required for MAP globe plotting. Decimal longitude of the pharmacy location. Example: 54.3773. Pair with latitude.
active optional Boolean. Reserved for future key suspension logic. Has no effect in the current Lambda implementation.
email DO NOT SET Leave blank. If an email is present, the Lambda sends a magic-link email instead of issuing a direct token. This breaks the kiosk flow.
ⓘ
UAE-resident pharmacies use a different SSM region and key prefix pattern (same as ALTHIQA* keys). Use --region me-central-1 for UAE SSM parameters.
4
Generate and Distribute the Pharmacy URL
Share with pharmacy staff

The pharmacy URL is constructed from the SSM key name. The ?site= parameter must exactly match the portion after /atlas/workspaces/ in SSM.

URL pattern
https://atlas.adherence.cc/pharmacy.html?site=PHRM-ROMAFARM001

The site code is normalized to uppercase automatically. Send the URL to the pharmacy site administrator. They should bookmark it on the shared dispensary tablet or kiosk device in a full-screen browser (kiosk mode recommended).

✓
Demo mode is available for onboarding and testing without Firebase writes: https://atlas.adherence.cc/pharmacy.html?demo=true This bypasses key validation and shows synthetic sample data (68 patients) in the dashboard.
5
Verify End-to-End
Browser test

Open the pharmacy URL in a browser and confirm each stage:

  • Loading spinner appears briefly while the key is being validated by the Lambda.
  • Setup screen loads (not an error screen). The pharmacy name field should be pre-filled from the SSM profile.
  • If parent_pi was set: a green "Connected to Workspace" badge appears above the form fields with the linked institution name.
  • Complete an assessment. On a red result, navigate to the alert screen.
  • If parent_pi was set: the "Push to [Institution] workspace" button should appear above the Copy and Email buttons.
  • Click the push button. Confirm a success toast appears and the button disables with a checkmark.
  • Log into the linked PI workspace in ATLAS and confirm the alert record appears in prescriber_alerts/{parent_pi}/ in Firebase (check Realtime Database console).
  • The pharmacy dashboard (Screen 5) should show only this site's records, not all pharmacy assessments.
Troubleshooting
SymptomCause and fix
Loading spinner hangs, then "Site Not Found" with the correct code Lambda cold start or SSM key missing. Confirm the key exists in SSM with aws ssm get-parameter --name "/atlas/workspaces/PHRM-XXX" --with-decryption. If absent, provision it (Step 3). If present but still failing, check Lambda logs in CloudWatch for the /validate-key invocation.
"No site code provided" error screen URL is missing ?site= parameter. The URL must include ?site=PHRM-XXXX. Check the bookmarked URL on the kiosk device.
Setup screen loads but pharmacy name is not pre-filled name field missing from SSM value. Update the SSM parameter to include "name": "Pharmacy Name" and test again. Existing Lambda cache clears on Lambda restart; force a cold start by updating an env var temporarily.
Green "Connected to Workspace" badge does not appear parent_pi not set in SSM profile. Update the SSM entry to include "parent_pi": "RESKEY-XXX". Also confirm parent_institution_name for the badge label.
"Push to Workspace" button not visible on alert screen Either the badge is missing (see above) or the result is not red. The push button only appears on red (high-risk) results. On green/amber results the standard Copy and Email actions are shown.
Firebase write fails after validation: "permission denied" Firebase rules not deployed yet (Step 2 was skipped). Run firebase deploy --only database from the firebase/ directory. Also confirm the Lambda is issuing a token with a workspace claim (check Firebase Auth console for the custom token UID).
Alert push button shows error toast prescriber_alerts node missing from deployed rules. Same fix as above: redeploy Firebase rules. Also check that parent_pi matches a valid workspace key (exact string match, case-insensitive at the application layer but case-sensitive in Firebase paths).
Dashboard shows "No assessments recorded" after completing a real assessment Workspace key mismatch. The dashboard queries pharmacy_assessments by workspace_key === _PG_SITE_CODE. Confirm the SSM key name matches the URL ?site= value exactly (both are normalized to uppercase). Old records stored before this update may have used a different casing and won't appear in the indexed query.
Assessment completes but does not appear as a dot on the ATLAS MAP globe latitude and longitude not set in SSM profile. The gateway reads geo coordinates from the workspace profile returned by the Lambda. Add latitude, longitude, country, country_iso2, and city to the SSM JSON and use --overwrite to update the existing key. Assessments recorded before the update will not be retroactively plotted.
Validation fails with "Request timed out" Lambda cold start exceeded 12-second timeout. The first request after a period of inactivity can be slow. Refresh the page to retry. If timeouts are frequent, consider configuring Lambda provisioned concurrency for the atlas-main function.
