MAP Pharmacy Gateway — Setup & Deployment

Complete guide to deploying the pharmacy assessment gateway, provisioning site keys, and connecting pharmacy locations to PI workspaces.

Platform: atlas.adherence.cc
File: pharmacy.html
Deploy target: Cloudflare Workers
Last revised: September 2026 (v2)
How the Gateway Works

The pharmacy gateway is a 5-screen kiosk page. The pharmacist signs in with their ATLAS workspace key, which is validated against SSM by the Lambda and exchanged for a scoped Firebase custom token. After sign-in the pharmacist completes an SDoH setup form and hands the tablet to the patient for the MAP assessment. Assessment data is written to the ATLAS assessments node and is immediately visible in the linked ATLAS workspace dashboard. When a high-risk result occurs, the pharmacist can push an alert directly to the linked prescriber workspace. The workspace profile (name, pharmacy type, geo coordinates) is read from SSM at login; no setup fields duplicate that information.

ⓘ
One key, two apps. A clinician workspace key works for both the pharmacy kiosk and the ATLAS staff dashboard. The pharmacist signs into pharmacy.html with the same key they use to log into atlas.adherence.cc. No separate site URL or second credential is needed. Pharmacy name, type, and geo data come from the SSM profile; no fields on the setup screen duplicate that.
⚠
Legacy URL mode still works. Adding ?site=PHRM-XXXX to the URL bypasses the login screen and auto-validates on load. This is retained for fixed kiosk deployments where the device never changes hands and no login prompt is desired. For multi-staff clinics, the login screen is the recommended approach.

Deployment Steps
1
Deploy pharmacy.html to Cloudflare
cloudbase_modular/ → atlas.adherence.cc

Run Wrangler from the cloudbase_modular directory. This deploys all static assets including pharmacy.html to the Cloudflare Workers site.

Terminal — from cloudbase_modular/
npx wrangler deploy

Wrangler will output the deployment URL and version ID. Verify at https://atlas.adherence.cc/pharmacy.html?demo=true — you should see the MAP Assessment loading spinner and then the setup screen.

⚠
Deploy only when ready. This command deploys the entire worker and all assets. If other changes in the working directory are not meant to go live, stash or commit them first.
2
Deploy Firebase Security Rules
firebase/ → adherence-project-2026 RTDB

The rules update restricts pharmacy_assessments writes to authenticated workspace tokens only (blocking anonymous writes), and adds the new prescriber_alerts node.

Terminal — from cloudbase_modular/firebase/
firebase deploy --only database

The Firebase console should show the rules version incrementing under Realtime Database → Rules. Confirm that pharmacy_assessments and prescriber_alerts are present in the deployed rules.

✓
Rules file used: firebase/database.rules.json (referenced by firebase/firebase.json). The file firebase-rules.json in the root is the working master copy and is kept in sync.
3
Provision a Clinician Workspace Key in AWS SSM
AWS SSM Parameter Store → /atlas/workspaces/CLIN-* (or any prefix)

Each pharmacy location gets one workspace key in SSM. The same key is used for both the pharmacy kiosk login and the ATLAS staff dashboard login. Pharmacy name, type, and all location metadata are stored in the SSM profile and applied automatically at login; staff do not enter them in the app.

The clinician role is the correct role for pharmacy keys. Only clinician and pharmacy roles are admitted by the pharmacy gateway; any other role is rejected at the login screen.

⚠
Do not include an email field in the JSON value. If an email is present, the Lambda triggers a magic link flow, which requires the pharmacist to check their email each session — incompatible with a shared kiosk. Omit email entirely; the key alone is the credential.
AWS CLI — provision a clinician key (UAE region)
aws ssm put-parameter \
  --name  "/atlas/workspaces/CLIN-XXXX-XXXX-2026" \
  --value '{"name":"Pharmacist Name","role":"clinician","country":"Country Name","country_iso2":"XX","city":"City Name","latitude":0.0000,"longitude":0.0000,"parent_pi":"INST-XXXX-XXXX-2026","parent_institution_name":"Clinic Name"}' \
  --type  SecureString \
  --region me-central-1

If the key already exists and you are updating it, add --overwrite to the command.

SSM JSON field reference:

Field Required Description
name required Pharmacy name. Displayed in the green "Connected to Workspace" badge on the setup screen and stored on every assessment record as pharmacy_name. There is no separate "Pharmacy Name" form field; this is the sole source.
role required Use "clinician" for pharmacists and pharmacy staff. The pharmacy gateway admits clinician and pharmacy roles; any other value is rejected at the login screen. The same key and role works for ATLAS staff dashboard login.
pharmacy_type optional Type of pharmacy location. Stored on every assessment record. Example values: "independent", "retail_community", "specialty", "hospital_clinical". This replaces the old setup-screen dropdown — it is now set once in SSM per location, not entered by staff each session.
parent_pi optional Links to a PI workspace. Set to the workspace key (e.g. "RESKEY-001") of the prescriber or research PI associated with this pharmacy. When present, the "Push to Workspace" button appears on the alert screen and alerts are written to prescriber_alerts/{parent_pi}/ in Firebase. Omit if the pharmacy is standalone.
parent_institution_name optional Human-readable label for the linked workspace — shown in the green "Connected to Workspace" badge on the setup screen and in the push button label. Falls back to parent_pi if omitted.
institution optional Pharmacy institution name. Used as the organisation header in the downloaded adherence report. Falls back to name if omitted.
country optional Country name (full). Stored on every assessment record. Used in reporting and data filters. Example: "United Arab Emirates", "Germany", "Philippines".
country_iso2 optional ISO 3166-1 alpha-2 country code. Example: "AE", "DE", "PH". Used for map filters and analytics grouping.
city optional City name. Stored on every assessment record for location-level reporting.
latitude optional Required for MAP globe plotting. Decimal latitude of the pharmacy location. Example: 24.4539 (Abu Dhabi). Without this field the assessment saves but does not appear as a dot on the ATLAS Mapbox global map.
longitude optional Required for MAP globe plotting. Decimal longitude of the pharmacy location. Example: 54.3773. Pair with latitude.
active optional Boolean. Reserved for future key suspension logic. Has no effect in the current Lambda implementation.
email DO NOT SET Leave blank. If an email is present, the Lambda sends a magic-link email instead of issuing a direct token. This breaks the kiosk flow.
ⓘ
UAE-resident pharmacies use a different SSM region and key prefix pattern (same as ALTHIQA* keys). Use --region me-central-1 for UAE SSM parameters.
4
Set Up the Kiosk Device
Share with pharmacy staff

Bookmark the base pharmacy URL on the shared dispensary tablet. No site code in the URL is needed — the pharmacist enters their workspace key on the login screen each session.

Kiosk URL (bookmark this)
https://atlas.adherence.cc/pharmacy.html

The pharmacist enters their clinician workspace key on the login screen and taps Sign In. After validation, the setup screen loads. The session persists until the browser tab is closed or refreshed.

Setup screen fields (in order): The pharmacist completes these fields before handing the tablet to the patient. All SDoH fields match the ATLAS MAP assessment exactly so records merge cleanly into the platform.

FieldRequiredNotes
Patient Reference CoderequiredChart number or visit ID. No personal data. Prefixed with the site code to form the patient_number record key.
Medical Condition Being TreatedoptionalSearchable single-select populated from the full ATLAS condition library (same data as MAP SDoH). English condition name stored in the record regardless of display language.
Number of MedicationsoptionalDropdown 1–10. Stored as num_medications.
Medication(s)optionalFree text. Stored as drug_type for compatibility with the ATLAS medication field.
GenderoptionalMale / Female / Other / Prefer not to say. Matches ATLAS SDoH options.
Age RangeoptionalUnder 18, 18–24, 25–34, 35–44, 45–54, 55–64, 65–74, 75 or older, Prefer not to say. Identical to ATLAS SDoH age ranges.
Highest Level of Educationoptional9-option list matching ATLAS SDoH education field. Stored as education_level.
Reported Adherence BarriersoptionalCheckbox chips: Cost, Side Effects, Forgetfulness, Complex Regimen, Access, Beliefs, Swallowing Difficulty, Injection Anxiety. Stored as adherence_barriers array.
Pharmacist NotesoptionalFree text clinical context. Stored as pharmacist_notes.
LanguageoptionalSets the display language for the MAP questions shown to the patient. Defaults to English.

Fixed kiosk mode (optional): If the tablet is permanently assigned to one location and you prefer no login prompt, append the key to the URL. The login screen is skipped and validation happens automatically on load.

5
Verify End-to-End
Browser test

Open https://atlas.adherence.cc/pharmacy.html in a browser and confirm each stage:

  • Login screen appears with a workspace key input field and Sign In button.
  • Enter the provisioned clinician key and tap Sign In. A brief "Verifying…" state appears while the Lambda validates.
  • Setup screen loads with the Patient Reference Code field at the top, followed by the full SDoH form.
  • If parent_pi was set: a green "Connected to Workspace" badge appears with the linked institution name. The pharmacy name from the SSM name field is visible there, not in a separate form input.
  • The Medical Condition field is a searchable select. Type a partial name to filter. Condition options are the full ATLAS library.
  • Age ranges show: Under 18, 18–24, 25–34, 35–44, 45–54, 55–64, 65–74, 75 or older, Prefer not to say.
  • Complete an assessment. On a red result, navigate to the alert screen.
  • If parent_pi was set: the "Push to [Institution] workspace" button should appear above the Copy and Email buttons.
  • Click the push button. Confirm a success toast appears and the button disables with a checkmark.
  • Log into the linked ATLAS workspace dashboard and confirm the assessment record appears. Verify that age_range, education_level, adherence_barriers, and pharmacist_notes are populated in the raw record.
  • The pharmacy dashboard (Screen 5) should show only records for this workspace, not all pharmacy assessments.
Troubleshooting
SymptomCause and fix
Login screen shows "This workspace key is invalid or has expired" Key not found in SSM or wrong region. Confirm the key exists with aws ssm get-parameter --name "/atlas/workspaces/PHRM-XXX" --with-decryption. If absent, provision it (Step 3). UAE keys require --region me-central-1. If the key exists but fails, check Lambda logs in CloudWatch for the /validate-key invocation.
Tapping Sign In shows "Verifying…" then hangs with no error Lambda cold start or network timeout. The request times out after 12 seconds and shows a timeout message. Wait a moment and try again — Lambda cold starts on first request after inactivity. If repeated failures occur, check CloudWatch for Lambda errors.
Workspace badge shows wrong name or no name name field missing or incorrect in SSM profile. Update the SSM parameter to include "name": "Pharmacy Name" and test again. The name is read from the profile at login time; re-login after updating SSM to see the change.
Green "Connected to Workspace" badge does not appear parent_pi not set in SSM profile. Update the SSM entry to include "parent_pi": "RESKEY-XXX". Also confirm parent_institution_name for the badge label.
"Push to Workspace" button not visible on alert screen Either the badge is missing (see above) or the result is not red. The push button only appears on red (high-risk) results. On green/amber results the standard Copy and Email actions are shown.
Firebase write fails after validation: "permission denied" Firebase rules not deployed yet (Step 2 was skipped). Run firebase deploy --only database from the firebase/ directory. Also confirm the Lambda is issuing a token with a workspace claim (check Firebase Auth console for the custom token UID).
Alert push button shows error toast prescriber_alerts node missing from deployed rules. Same fix as above: redeploy Firebase rules. Also check that parent_pi matches a valid workspace key (exact string match, case-insensitive at the application layer but case-sensitive in Firebase paths).
Dashboard shows "No assessments recorded" after completing a real assessment institution_code mismatch. The ATLAS workspace dashboard filters records by institution_code matching the logged-in workspace key. The pharmacy gateway sets institution_code to parent_pi from the SSM profile. Confirm parent_pi in the pharmacy key's SSM entry exactly matches the institution's ATLAS workspace key (uppercase).
Condition dropdown is empty or shows no options modules/lang-conditions.js failed to load. Open browser DevTools and check the Console for script errors on the lang-conditions.js import. Confirm the file exists at cloudbase_modular/modules/lang-conditions.js and that a fresh deploy has been run.
Assessment completes but does not appear as a dot on the ATLAS MAP globe latitude and longitude not set in SSM profile. The gateway reads geo coordinates from the workspace profile returned by the Lambda. Add latitude, longitude, country, country_iso2, and city to the SSM JSON and use --overwrite to update the existing key. Assessments recorded before the update will not be retroactively plotted.
Validation fails with "Request timed out" Lambda cold start exceeded 12-second timeout. The first request after a period of inactivity can be slow. Refresh the page to retry. If timeouts are frequent, consider configuring Lambda provisioned concurrency for the atlas-main function.
